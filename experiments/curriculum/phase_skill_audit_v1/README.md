# BC phase-skill diagnosis v1

Purpose: distinguish inaccurate individual BC heads from unsuitable states
inherited from earlier phases before defining a phase-aware curriculum.
Reference: three immutable B models, ordinary mixed-batch BC, 30,000 updates.
No optimizer updates, no new training labels, no checkpoint selection.

## Protocol

1. Reconstruct all expert phase/action labels from the original low-dimensional
   trajectories and compare them with the archived training arrays. Whole-demo
   train/validation split remains unchanged. Timestamps are not required.
2. Measure action errors and completion predictions on the existing validation
   split, separately for each phase.
3. Run each unchanged model in 20 existing development scenes with three cubes.
4. For five development scenes, execute the expert until Lift, Travel, Descend
   or Open begins, at both placements. Compare the expert continuation with each
   BC head from that same prefix. Both the full simulation state and entire
   prefix history must have identical hashes across comparison branches.
5. Separate starts eligible for the tested phase from unsuitable starts. Only
   eligible starts with a successful expert positive control enter the isolated
   success denominator. Inspect complete rollouts separately.

The 220 episodes comprise 40 shared expert controls, 120 isolated BC trials and
60 complete BC rollouts. The fixed wall-clock ceiling is 20 minutes. `--smoke`
reduces this to 17 technical episodes and is excluded from scientific results.

## Criteria and limitations

Lift requires a grasp, at least 30 mm lift and reaching the expert lift target
within 6 mm. Travel requires a grasp, lateral error <=15 mm and >=120 mm
vertical clearance over the target. Descend requires cube contact, lateral
error <=9 mm and target height 40 +/-8 mm. Open requires strict contact-free
stable stacking for 10 frames at the first placement, 50 at the second.
The final-release clock is capped at 17 input steps as in the prior comparison.

These are diagnostic criteria, not four independent proofs of task success.
In particular, a Lift head completing before the exact expert target can still
feed a successful Travel phase. A Descend head completing before contact can
still be recovered by Open. Inspect physical margins and subsequent outcomes.
`full_physically_ready_at_last_frame` checks an instantaneous phase condition;
it does not establish the 50-frame final success criterion.

Expert-prefix trials test clean expert states, not states generated by BC.
The reference extends the expert's Open hold for the stability check, without
adding retreat or training examples. Reserved confirmation scenes remain closed.
Small conditional samples are suitable for choosing the next diagnostic,
not for claiming statistically established improvement.

## Run and artifacts

```powershell
praxis/.venv/Scripts/python.exe -m unittest discover -s experiments/curriculum/phase_skill_audit_v1 -p test_audit.py
praxis/.venv/Scripts/python.exe experiments/curriculum/phase_skill_audit_v1/audit.py --output praxis/results/curriculum/phase_skill_audit_v1/run_001
```

Use a new output directory for each run. `plan.json`, `provenance.json`,
`segmentation_audit.json`, `offline_phase_metrics.json`, `expert_reference.json`,
`isolated_phases.json`, `full_rollouts.json`, `summary.json` and `status.json`
preserve criteria, input hashes, per-trial measurements and completion state.
Compressed traces contain development diagnostics only. Original model bundles
retain their optimizer and RNG states for separately specified continuations.
